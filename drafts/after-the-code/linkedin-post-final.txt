𝗦𝗵𝗶𝗽 𝗕𝗲𝘁𝘁𝗲𝗿, 𝗡𝗼𝘁 𝗠𝗼𝗿𝗲

A few months ago I wrote that a software engineer's job was never the code. It was always to deliver working software.

Gen AI now writes a large share of the implementation. That frees up hours. The question is what we do with them.

The easy answer is to ship more. More features per sprint. More releases per week. Faster ticket closure.

In some work, that is fine. A prototype or an internal tool can move fast and learn fast.

In healthcare, it is not. A fast release that breaks a clinical workflow costs far more than a slow one that works. Here, the time AI gives back should turn into value, stability and quality — not volume.

𝗠𝗼𝗿𝗲 𝗼𝘂𝘁𝗽𝘂𝘁 𝗶𝘀 𝗻𝗼𝘁 𝘁𝗵𝗲 𝗴𝗼𝗮𝗹. 𝗕𝗲𝘁𝘁𝗲𝗿 𝗼𝘂𝘁𝗰𝗼𝗺𝗲𝘀 𝗮𝗿𝗲.

Where I think the freed hours belong:
 • Gates in the codebase — tests, type checks, security scans, architecture rules
 • Secure coding, and knowing what to look for in review
 • Specifying clearly, because a vague requirement now becomes a confident, wrong pull request
 • Fundamentals — system design, data modeling, the domain we serve
 • Keeping up with Gen AI, time-boxed, so it does not become a treadmill

𝗚𝗮𝘁𝗲𝘀 𝗰𝗼𝗺𝗲 𝗳𝗶𝗿𝘀𝘁. Every change an agent makes has to pass through them. An hour spent on a gate pays off on every change after it, whether a person or an agent wrote it.

The measure I care about is not how many tickets we close. It is how many never get opened — because quality went up and fewer things broke.

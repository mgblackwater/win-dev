The code writes itself.
What do you do now?

AI agents now write most of the code. The hours they free up don't stay free. They move to specifying, checking and owning the work. The goal is more value and higher quality, not more output. This page maps where that time should go.

02 · priority.set(value > velocity)

Deliver more value, not more changes

Agents make it possible to ship more. That doesn't mean we should. How we spend the saved time depends on the kind of work. In healthcare, a fast release that breaks a clinical workflow costs far more than a slow one that works.

Prototypes, internal toolsLearn fast. Throwaway is fine.
Business appsBalance speed with reliability.
Healthcare, finance, safety-criticalStability, safety and correctness first.
Not the goal

Using saved time to ship more

  • More features per sprint
  • More releases per week
  • Faster ticket closure
The goal

Using saved time to ship better

  • Changes that clearly add value and are well understood
  • Fewer tickets: higher quality means fewer breaking changes, and fixing root causes stops the same bugs coming back
  • Deeper testing and edge cases
  • Security and compliance review
  • Paying down risky legacy code
  • Validating features with real users
03 · pipeline.guard()

Gates keep quality high as agents write more code

Every change an agent makes has to pass through your guardrails. Work you put into the gates pays off on every future change, whether a person or an agent wrote it. The aim is stable releases, not more releases.

04 · focus.sort(by: leverage)

Five core areas to invest in

Ranked by long-term value. The higher an area sits, the more every future change benefits from it.

1

Gates and codebase improvements

Tests, linters, type checks, security scans and architecture rules in CI. An agent working inside strong guardrails can be trusted with much more.

2

Secure coding

Agents repeat insecure patterns confidently and at volume. Learn what to look for in review. This matters most in regulated domains such as healthcare.

3

Communication

Clear specs, explained trade-offs, pushing back on vague asks. A prompt is a spec for an agent, so this is now a core engineering skill.

4

Learning, deep rather than wide

System design, data modeling, distributed systems and your business domain. This is how you spot when an agent's design is subtly wrong.

5
Time-box it

Keeping up with AI

Tools change every month, so following all of it becomes a treadmill. An hour or two a week is enough. Learn the patterns that last: context, verification, decomposition.

05 · focus.include(overlooked)

Easy to overlook

These rarely make it into a growth plan, but they matter just as much once agents do the typing.

Get closer to users

When code is cheap, the engineer who knows why a feature exists is worth more.

Observability

Know how the system really behaves in production, so stability and quality are measured, not assumed.

Mentoring

The old learning path of writing lots of code is getting shorter. Someone has to teach judgment.

Rest

Reviewing all day is draining. If every freed hour becomes more output, burnout comes sooner.
